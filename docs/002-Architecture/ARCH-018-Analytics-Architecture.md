## Overview

Ferret V2.5 adds business intelligence and executive dashboards to the platform. This document defines:
1. The analytics event model (what gets measured)
2. The dashboard architecture (how it is presented)
3. The metric categories (what decisions are driven by the data)

The analytics layer is local-first: all data is stored in `.ferret/telemetry/analytics.db`. Enterprise aggregation (org-level dashboards) is V3.

## Analytics Event Model

Analytics events are structured records written to `analytics.db`. Events are append-only (never updated). Retention is configurable (default: 90 days).

### Event Schema

```
AnalyticsEvent
  Id           GUID
  EventType    string (see taxonomy below)
  Timestamp    DateTimeOffset
  WorkspaceId  string
  SessionId    string
  DurationMs   int?
  Metadata     JSON (event-specific payload)
```

### Event Taxonomy

**Workspace Events**

| Event | Trigger | Key Metadata |
|---|---|---|
| `WorkspaceCreated` | `ferret workspace init` | WorkspaceType, ContextOsVersion |
| `WorkspaceOpened` | `ferret workspace status` or engine load | WorkspaceId, RootPath |
| `WorkspaceUpgraded` | Schema migration applied | FromVersion, ToVersion |

**Indexing Events**

| Event | Trigger | Key Metadata |
|---|---|---|
| `RepositoryIndexed` | `ferret index` completes | FilesIndexed, DurationMs, IndexType |
| `IndexUpdated` | Incremental index update | FilesAdded, FilesRemoved, FilesModified |
| `IndexFailed` | Index operation fails | ErrorCode, ErrorMessage |

**Connector Events**

| Event | Trigger | Key Metadata |
|---|---|---|
| `ConnectorSynced` | Connector sync completes | ConnectorType, RecordsSync'd, DurationMs |
| `ConnectorFailed` | Connector sync fails | ConnectorType, ErrorCode |
| `ConnectorHealthChecked` | `ferret doctor` runs | ConnectorType, IsHealthy |

**Context & AI Events**

| Event | Trigger | Key Metadata |
|---|---|---|
| `ContextGenerated` | Context assembly completes | TokenCount, FilesIncluded, DurationMs |
| `ContextCompressed` | Context compression applied | BeforeTokens, AfterTokens, CompressionRatio |
| `PromptGenerated` | Prompt assembled for model | PromptType, TokenCount |
| `AIRequestExecuted` | Model invocation completes | ModelId, InputTokens, OutputTokens, DurationMs, Cost |
| `SearchExecuted` | `ferret search` runs | QueryType, ResultCount, DurationMs |

**Knowledge Events**

| Event | Trigger | Key Metadata |
|---|---|---|
| `KnowledgeAdded` | Entity or relationship written | EntityType, ConnectorType |
| `KnowledgeQueried` | Knowledge graph queried | QueryType, ResultCount |
| `SnapshotCreated` | Workspace snapshot taken | SnapshotId, GitCommit |
| `WorkspaceRestored` | Snapshot restored | SnapshotId, GitCommit |

**Plugin Events**

| Event | Trigger | Key Metadata |
|---|---|---|
| `PluginLoaded` | Plugin activated | PluginId, PluginVersion |
| `PluginFailed` | Plugin raises unhandled exception | PluginId, ErrorCode |
| `ReviewCompleted` | AI review pipeline completes | ReviewType, FilesReviewed, FindingsCount |

## Dashboard Architecture

### Delivery Mechanism

Dashboards are static HTML files generated by `Ferret.Dashboard` and written to `.ferret/artifacts/dashboards/`. No web server required — open in any browser. Optionally served by `ferret serve --dashboard` (adds minimal HTTP server in V2.5).

### Dashboard Types

**Ferret Dashboard (Main)**

The entry-point dashboard. Shows:
- Workspace health (connector statuses, index freshness)
- Quick stats (files indexed, last sync, knowledge entities)
- Recent activity (last 10 events, last 5 searches)
- Links to all sub-dashboards

**Engineering Dashboard**

For individual developers:
- Daily context usage (token count, cost estimate)
- Searches performed
- Context assembly efficiency (compression ratio trend)
- Most-used connectors

**Repository Dashboard**

For tech leads:
- Codebase coverage (% indexed, % in knowledge graph)
- Index freshness (time since last update per connector)
- Hot files (most frequently included in context)
- Knowledge debt (files with no entities, no decisions)

**Knowledge Dashboard**

For architects:
- Entity count by type (services, functions, decisions)
- Relationship density
- Knowledge graph growth trend
- ADR coverage (% of architectural decisions captured)

**AI Dashboard**

For engineering managers:
- Total AI token usage by day/week/month
- Cost trend (requires model pricing config)
- Model usage distribution
- Context efficiency (average tokens per useful response)

**ROI Dashboard**

For executives:
- Estimated developer hours saved (based on search queries + context generation)
- Knowledge base growth (year-over-year if workspace is old enough)
- Connector coverage (how many data sources are connected)

**Executive Dashboard**

Summary for non-technical stakeholders:
- "Ferret is connected to N sources of engineering knowledge"
- "Your team has made N architecture decisions this quarter"
- "Average context generation time: Xms"

## Reporting

**Weekly Report** — Auto-generated markdown + HTML. Contains:
- Top 10 searches
- Files changed vs indexed
- Connector sync summary
- Knowledge additions

**Sprint Report** — Generated at `ferret report --sprint`. Contains weekly report plus:
- ADRs written this sprint
- Technical debt added/resolved
- AI token cost

**Executive Report** — Generated at `ferret report --executive`. Metrics only, no code references.

## Metrics Categories

### Productivity Metrics

- Developer time saved (estimated from context generation events)
- Knowledge reuse rate (how often existing context is found vs re-generated)
- Search success rate (searches that result in context generation)

### Usage Metrics

- Daily/weekly active workspaces
- Commands run per day
- Searches per day
- Context generations per day

### Cost Metrics

- AI model tokens per day (by model)
- Estimated cost per day (configurable pricing table)
- Cost per search
- Cost per context window

### Quality Metrics

- Index freshness (time since last full index)
- Connector health scores
- Knowledge completeness (% of codebase with entities)
- Context compression efficiency

## Data Collection Strategy

### Privacy First

- All analytics data is local by default
- No data leaves the machine without explicit opt-in
- Sensitive content (file paths, entity names) is anonymized before any opt-in sharing
- Users can purge analytics at any time: `ferret analytics clear`

### Sampling

For high-frequency events (every search, every context generation), events are written asynchronously with a bounded queue. If the queue is full, events are dropped — analytics must never block the main path.

### Retention

Default: 90 days. Configurable in `runtime.json`:

```json
{
  "analytics": {
    "retentionDays": 90,
    "enabled": true
  }
}
```
