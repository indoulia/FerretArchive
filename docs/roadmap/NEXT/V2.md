# Ferret v2 — Workspace Intelligence Platform

**Status:** Approved by Founder directive, in execution. This page is a product-strategy summary only — all engineering detail lives in [`Workspace-Intelligence/`](../Workspace-Intelligence/README.md), which remains authoritative for this milestone.

## What It Is, At the Product Level

A workspace stops being a checkout of one repository and becomes a queryable unit of knowledge that can *reference* other workspaces as read-only dependencies — the same relationship a package has to its dependencies. Repository boundaries become an implementation detail; the workspace boundary is what a question is scoped to.

## Why It Belongs in Ferret

Directly matures [FEP-002-CAP-11 Federation](../../FEP/capabilities/FEP-002-CAP-11-Federation.md) — extending the capability model across workspaces once the per-workspace model is functioning. It is additive: every existing single-repo workspace keeps working unchanged.

## Business & User Value

- **Coverage gap closed.** Content in a shared library, an infra repo, or a docs-only repo becomes visible to questions asked from the primary repo, without copying it in.
- **Duplication pressure removed.** Teams no longer need to re-index the same content into every repo that needs it — the stated reason "no duplication, no re-indexing" was ever a requirement.
- **Adoption friction reduced.** A team's existing single-repo Ferret usage is unaffected; referencing another workspace is additive, not a migration.

## Scope Boundary (this milestone)

Deliberately excludes: full enterprise RBAC beyond a 4-role subset, org-wide analytics/billing, cross-*organization* federation ("Ferret Hub"), and 100K-repository registry scale. Each exclusion traces to a specific future-roadmap deferral — see [`../Future/Deferred-Scope.md`](../Future/Deferred-Scope.md).
