## Findings

1. **Bug — `read_document` could not resolve any ID `search` itself returns (100% failure).** `SearchTool` printed only `hit.CanonicalUri`, never `hit.DocumentId.Value` — the field `ReadDocumentTool` actually looks up by. Every ID shape derived from a live search result failed with "Document not found." **Fixed via TDD** (commit `3ce7d44`): `SearchTool` now prints `Document ID: {hit.DocumentId.Value}` alongside the URI. Full suite green.
2. **Bug — `ferret_context`'s `max_tokens`/`max_documents` had no effect when the single top-scoring document alone exceeded the budget.** `ContextAssembler`'s budget loop exempts the first included document from the check (so a non-empty query never returns zero documents) — but that document's content was then included *unbounded*, so two different `max_tokens` values on the same oversized top hit produced byte-identical output. Live symptom: `ferret_context("What is Ferret?")` errored past the client's own display limit regardless of an explicit `max_tokens: 2000`. **Fixed via TDD** (commit `befe248`): truncate that document to fit the budget instead of returning it unbounded. Full suite green.
3. **Bug — `.worktrees/v2-workspace-intelligence/` indexed as ordinary content, duplicating the entire corpus.** `FilesystemConnector.HardcodedSkipDirs` excluded `.git`/`.ferret`/`node_modules`/`bin`/`obj`/`packages` but not `.worktrees` — every single search this session returned the same document twice (once from `docs/...`, once from the worktree copy), halving the effective result count everywhere. **Fixed via TDD** (commit `200b3bc`): added `.worktrees` to the skip set.
4. **Investigated a suspected hyphenated-exact-match search bug (`ADR-0026`, `Decision-Register` both returned zero live results) — turned out already fixed in source, not a new defect.** Traced toward `QueryTranslator.EscapeKeyword`, expecting a repeat of #15 (`nem-3795`, fixed 2026-07-05 via commit `366cc3d`). A real-SQLite-FTS5 integration test proves the current source handles this correctly (`ADR-0026` matches a seeded document containing it). The live zero-result behavior is therefore most likely explained by the running MCP server process predating commit `366cc3d`, consistent with this project's own documented "fixed in source, not yet in the installed binary" release-lag pattern (see 2026-07-05 log, item 21). Added a permanent regression test anyway (commit `8bcddad`) so this exact scenario is pinned either way.
5. **Verified issue #9 (`IndexPipeline` attempts to open directory assets) is already fixed, just left open.** Commit `e5f344b` (predates this session) already added the `AssetKind.Directory` skip the issue asks for, with a passing regression test. No code change needed — issue-hygiene gap only. *Attempted to close #9 with a verification comment; blocked by the auto-mode permission classifier ("agent did not create this issue this session") — left open, flagged below for the user.*
6. **Fixed issue #21 (`ContextAssembler` silently swallows search failures as "0 documents," indistinguishable from a legitimately empty result).** Added additive `SearchFailed`/`Diagnostics` fields to `ContextPackage` (mirroring the existing `SearchServiceResult.Diagnostics` pattern already used elsewhere in the codebase) and surfaced them in `ToPromptString()` as `"Search failed: <reason>"`. Purely additive — no existing field renamed or removed, no consumer contract broken. **Fixed via TDD** (commit `db40d30`), covering both `Ferret.AI.Tests` and `Ferret.Mcp.Tests`. Full 28-project solution suite green.
7. **Independently reproduced issue #30** (`ferret context`/`search`: natural-language questions frequently return zero results under strict implicit-AND) with a fresh example this session: `"why did we choose SQLite FTS5 instead of a vector database"` → 0 results, despite the answer existing in the corpus under different wording (surfaced minutes earlier via `"indexing pipeline"`). **Not implemented** — real query-relaxation design decision (OR-fallback, stopwords, or a hint), per the issue's own "Needs Founder Decision" disposition. Corroborating evidence, not attempted here.
8. **MCP tool-surface scope gap (new, not filed as an issue this session — see note below).** The four MCP tools exposed here (`search`, `ferret_context`, `read_document`, `workspace_status`) have no equivalent to the CLI's workspace/federation management (`workspaces query`, `add-repo`, `add-reference`) that the 2026-07-04 Sprint 1 dogfooding validated directly. An AI agent restricted to MCP cannot exercise or verify any of Sprint 1's federation findings. Worth a Founder decision on whether this is intentional scope or a gap to close.
9. **Root-caused issue #17 (`ferret watch` latency) with hard measurement — confirmed, not fixed.** `WatchCommandHandler.ProcessChangesAsync` calls the *full* `IIndexPipeline.RunAsync` (a complete workspace discovery + fingerprint-check walk) on every debounced change batch, regardless of how many files actually changed. Timed a real `ferret index` run against this repo (1,253 discovered, only 38 actually re-indexed): **23.22s wall time** — directly in the range of the "more than 27s" gap the issue reported, and explains the observed pattern (DB file touched early from an unrelated earlier file in the walk order; the just-changed file isn't reached/written until much later). **Not fixed**: the real fix (reindex only the changed file(s), not the whole workspace) needs a new single-asset lookup capability on `IAssetSource` — every connector implementation would need to support it, and `IAssetSource` currently only exposes bulk `DiscoverAsync`. That's an interface-level extension across the connector abstraction, not a bounded one-file correction — flagged for a Founder decision rather than freelanced.
10. **Fixed issue #18 (`ferret doctor`'s freshness check has no git-branch awareness).** `IndexPipeline` now resolves the current git HEAD SHA directly from `.git/HEAD` + loose/packed refs (new `GitHeadResolver`, no `git` binary invocation) and records it in the existing `IIndexStateStore` at the end of each run (additive `SetIndexedGitHeadAsync`/`GetIndexedGitHeadAsync`, with backward-compatible on-disk format migration so pre-existing state files don't lose their fingerprints). `IndexFreshnessCheck` compares recorded vs. current HEAD and warns on mismatch. **Fixed via TDD** (commit `b607428`). Full suite green.
11. **Fixed issue #25 (`ferret status` hardcoded stub).** `ferret start` now writes its PID + start time to `.ferret/runtime-status.json` once the runtime is ready, and removes it on clean shutdown; `ferret status` reads it and verifies the PID is still alive, reporting real state instead of an unconditional "not running." Stale markers from a crashed process are detected and cleaned up automatically. Documented limitation: PID reuse can't be perfectly ruled out without a real IPC health protocol — accepted for this fix rather than building the full named-pipe design the issue's comment sketches. **Fixed via TDD** (commit `3630094`). Full suite green.
12. **Fixed issue #23 (`--passages` silent no-op).** Real passage-level search (chunking + scoring) is genuine unscoped feature work not attempted here; the actual defect — the flag silently pretending to work — is fixed by making `ferret search --passages` fail with a clear, actionable error instead of quietly returning file-level results. **Fixed via TDD** (commit `3577ce9`). Full suite green.
