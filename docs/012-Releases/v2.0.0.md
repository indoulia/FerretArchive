# Ferret v2.0.0 — Workspace Intelligence Platform

```bash
ferret workspaces create my-service
ferret workspaces add-repo my-service .
ferret workspaces add-reference my-service shared-lib
ferret workspaces query my-service "what implements the interface this service depends on?"
```

## Overview

Ferret v2.0 generalizes the workspace boundary past a single repository. A workspace stops
being a checkout of one repository and becomes a queryable unit of knowledge that can
*reference* other workspaces as read-only dependencies — the same relationship a package has
to its dependencies. Repository boundaries become an implementation detail; the workspace
boundary is what a question is scoped to.

Every existing single-repo workspace keeps working unchanged. Referencing another workspace
is additive, not a migration — no action is required to keep using Ferret exactly as before.

## Major Features

**Workspace Intelligence**
- `ferret workspaces create/list/show/add-repo/remove-repo/remove` — group related repos
  under a queryable workspace, identified by canonicalized git remote (with a fallback for
  repos with no remote or multiple remotes).
- Existing single-repo workspaces are auto-migrated into the registry the first time any
  `ferret workspace` command runs after upgrading — no user action required.

**Federated Search**
- `ferret workspaces add-reference/remove-reference` (with cycle detection) lets one
  workspace reference another as a read-only dependency.
- `ferret workspaces query` fans a query out across a workspace and everything it references,
  merging correct, cited results with zero index duplication on disk.
- `ferret workspaces pin-reference/unpin-reference` pins a reference to a specific content
  state and fails closed (excluding only the stale source) if that content changes underneath it.

**MCP Integration**
- `workspace_list` and `workspace_query` MCP tools give AI-agent hosts (Claude Desktop,
  Cursor, and other MCP clients) the same federation capability the CLI has.

**CLI**
- `ferret workspaces remove` for bulk cleanup of registered workspaces.

**Performance Improvements**
- A federated query cache and a workspace-reference topology cache, together with
  cross-workspace pull-based invalidation, keep federated queries fast as workspace count
  and reference depth grow.
- Cross-source ranking normalization: results from different workspaces are now scored on a
  comparable scale, so a smaller, more relevant workspace's results aren't buried under a
  larger workspace's merely-adequate ones.

## Engineering Highlights

- **Architecture stabilization** — the federation architecture was validated through two
  dedicated multi-repository dogfooding sprints (real usage, not synthetic tests), with a
  follow-up engineering analysis and hardening pass before this release.
- **Performance improvements** — a federated-query cache regression found during real-scale
  dogfooding was root-caused and fixed prior to release.
- **Repository modernization** — the workspace boundary is now a first-class, versioned,
  atomically-persisted registry entry rather than an implicit property of "the current checkout."
- **Workspace Graph** — `Ferret.Workspace.Graph` and `Ferret.Knowledge.Federation` introduce
  the registry, reference graph, and federated knowledge store underpinning all of the above.
- **Engineering quality** — structured logging was added to the federation/cache query path
  specifically because its absence made a real regression harder to diagnose than it should
  have been; the test suite grew from a 1,466-test baseline to 1,601 passing tests with zero
  regressions, and all architecture-fitness tests continue to pass.

## Breaking Changes

None.

## Upgrade Notes

No action required. Existing single-repo workspaces are auto-migrated into the workspace
registry (as a `kind: "personal"` entry) the first time any `ferret workspace`/`ferret
workspaces` command runs after upgrading. Existing `ferret index`/`ferret search` and
`ferret workspace init`/`status` behavior is unaffected.

## Known Limitations

- **Federated context optimization (scope narrowing, compression)** is deferred to v2.1.
  Federated queries already return correct, cited results; further token-cost reduction for
  very large multi-workspace corpora is not yet implemented — real-scale validation of the
  approach doesn't exist yet beyond a Python simulation.
- **Usage analytics, cost dashboards, and observability rollups** are not part of this release.
- **Multi-role sharing/RBAC** (`ferret workspace share`, role-based access) is not part of this
  release, pending a Founder decision on the sharing-scope ADR.
- The workspace registry is validated at typical team scale; very large (100,000+) workspace
  registries are a distinct, not-yet-designed scaling problem.

## Future Roadmap

Ferret's next generations build on this foundation without changing its Context OS boundary:
v2.1 may revisit federated context optimization if real usage data justifies it; v3 matures
provenance and access control into full enterprise trust and governance; v4 extends
federation across organizational boundaries. See the living
[Ferret Product Roadmap](../roadmap/FERRET-PRODUCT-ROADMAP.md) for detail — nothing there is
an engineering commitment until promoted through a future Engineering Program.
