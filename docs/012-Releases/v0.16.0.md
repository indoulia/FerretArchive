# Ferret v0.16.0 — Enterprise Content Pack 1

**Ferret now indexes enterprise documents. Point it at a workspace full of PDFs, Word documents, and Excel workbooks — not just text, Markdown, and JSON — and search across all of them.**

```bash
npm install -g @indoulia/ferret
ferret index .
ferret doctor          # see every installed parser and what it can read
```

## Why this release matters

Through v0.15.0, Ferret only parsed text-family formats (plain text, Markdown, JSON). Real workspaces are full of PDFs, Word documents, and spreadsheets — design docs, requirements, bug exports, sprint backlogs, risk registers. **Enterprise Content Pack 1** brings those formats into the index, taking Ferret from 3 to **7 parsers**.

This release also delivers the **public download mirror fix**: after the source repository was made private, anonymous `npm install -g @indoulia/ferret` broke (GitHub 404s release assets on private repos). Downloads now come from the public `indoulia/ferret-dist` mirror, so installation works again from v0.16.0 onward.

## What's new

**New parsers (7 total: PlainText, Markdown, JSON, CSV, PDF, Word, Excel)**
- **CSV / TSV** — dependency-free, structure-aware parsing (`Data` kind). Ideal for Jira/ADO exports, RTMs, and backlogs.
- **PDF** — text and lightweight metadata extraction via PdfPig.
- **Word (.docx)** and **Excel (.xlsx)** — via Open XML. Excel uses streaming extraction for large workbooks, resolves shared strings, and reads cached cell values (no formula recomputation).
- Parsers extract text and lightweight metadata only — no chunking, tokenizing, embedding, summarization, or spreadsheet calculation.

**Smarter file classification**
- MIME resolution reclassifies PDF/DOCX/XLSX as binary-parseable, with an expanded code/config map and a binary denylist.
- **Filename resolution** makes extensionless files like `Dockerfile` and `Makefile` first-class citizens.
- New `ParserOptions.MaxExtractedCharacters` extraction cap (default: unlimited; sets `Truncated` metadata when applied).

**`ferret doctor` Parser Platform report**
- Lists installed parsers in registration order, extension coverage (parseable vs. opaque), and the parser packages providing them.
- `ferret doctor --verbose` now runs recursively and shows all opaque extensions plus per-parser priority, media type, and parseable MIME types.

**Performance benchmarks**
- A deterministic enterprise corpus generator and BenchmarkDotNet suite for parser and indexing throughput.

## Fixes

- **Public download mirror.** `npm install -g @indoulia/ferret` now downloads release binaries from the public `indoulia/ferret-dist` mirror instead of the (now-private) source repo, restoring anonymous installation. Overridable via `FERRET_DIST_OWNER` / `FERRET_DIST_REPO` / `FERRET_DIST_RELEASE_ENDPOINT`. The release pipeline verifies the download endpoint is anonymously reachable before publishing.

## Install / Upgrade / Uninstall

| Action | Command |
|---|---|
| Install | `npm install -g @indoulia/ferret` |
| Upgrade | `npm update -g @indoulia/ferret` |
| Uninstall | `npm uninstall -g @indoulia/ferret` |

Install locations: Windows `%LOCALAPPDATA%\Programs\Ferret` · macOS `~/Library/Application Support/Ferret` · Linux `~/.local/share/ferret`.

## Assets in this release

- `Ferret-0.16.0-win-x64.zip`, `Ferret-0.16.0-linux-x64.zip`, `Ferret-0.16.0-osx-arm64.zip`, `Ferret-0.16.0-osx-x64.zip` — self-contained, single-file binaries.
- `SHA256SUMS.txt` — checksums for all archives.
- `release-manifest.json` — the machine-readable distribution contract (`schemaVersion: 1`).
- `*.nupkg` — NuGet packages.

Verify a download manually:

```bash
sha256sum -c SHA256SUMS.txt
```

## Known limitations

- **macOS binaries are unsigned and unnotarized.** macOS users will see a Gatekeeper prompt; allow the binary in System Settings → Privacy & Security. Signing is deferred to a future milestone.
- **Deferred to Enterprise Content Pack 2:** PowerPoint (.pptx), HTML, XML, RTF, YAML, TOML, INI. DOCX comments, OCR, and legacy `.doc`/`.xls` are out of scope.
