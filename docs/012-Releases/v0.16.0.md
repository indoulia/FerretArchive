# Ferret v0.16.0 — Enterprise Content Pack 1

```bash
npm install -g @indoulia/ferret
ferret index .
ferret doctor          # see every installed parser and what it can read
```

## Highlights

Enterprise Content Pack 1 transforms Ferret from a source-and-text search tool into a multi-format enterprise knowledge index.

This release expands parser support from **3 formats to 7**, adding:

- **PDF** (`.pdf`)
- **Word** (`.docx`)
- **Excel** (`.xlsx`)
- **CSV / TSV** (`.csv`, `.tsv`)

Ferret can now search across source code, documentation, structured data, and enterprise documents through a single index. It also **restores anonymous `npm install`**, which broke when the source repository was made private.

## Supported file types

Ferret recognizes **79 parseable extensions** (plus filename-based matches like `Dockerfile` and `Makefile`). Code and text formats are indexed as text; binary documents are extracted to text and lightweight metadata.

| Category | Formats |
|---|---|
| Source code & text | C#, Java, Kotlin, Go, Rust, C/C++, Python, Ruby, PHP, Swift, Scala, JavaScript, TypeScript, Shell, SQL, HTML, CSS, XML, YAML, TOML, Markdown, JSON, … |
| Structured data | CSV, TSV |
| Documents | PDF (`.pdf`), Word (`.docx`), Excel (`.xlsx`) |

Parsers extract text and lightweight metadata only — no chunking, tokenizing, embedding, summarization, or spreadsheet calculation. Excel uses a streaming reader for large workbooks, resolves shared strings, and reads cached cell values (no formula recomputation).

## Diagnostics

`ferret doctor` gains a **Parser Platform report**:

- Installed parsers, listed in registration order
- Extension coverage summary (parseable vs. opaque)
- Parseable vs. opaque binary reporting
- Parser packages providing each format
- `ferret doctor --verbose` now runs recursively and adds per-parser priority, media type, and parseable MIME types plus the full opaque-extension list

## Performance

Measured on the reference benchmark corpus (laptop-class, indicative — re-run on target hardware):

- **PDF:** ~2,900 documents/sec
- **Word (.docx):** ~600 documents/sec
- **Excel (.xlsx):** ~122 documents/sec
- **Parser dispatch overhead:** negligible — media-type resolution and parser selection add no measurable cost on top of the parse itself
- A 50k-row workbook parses via the streaming reader with ~326 MB peak working set (linear in row count, no runaway)

See `docs/benchmarks/parser-pack-1/README.md` for the full report and methodology.

## Benchmarking

Added a deterministic enterprise corpus generator and a BenchmarkDotNet suite covering:

- Parser throughput
- Dispatcher overhead
- Large-workbook memory profile

This establishes a reproducible performance baseline for future releases (see `docs/benchmarks/parser-pack-1/future-benchmarks.md` for the planned end-to-end indexing and search-latency benchmarks).

## Distribution

The global npm installer once again works for anonymous users.

Binary downloads are now served from the public `indoulia/ferret-dist` release mirror rather than the (now-private) source repository — GitHub only serves release assets anonymously from public repos, which is what the installer's `postinstall` step needs. The download host is overridable via `FERRET_DIST_OWNER` / `FERRET_DIST_REPO` / `FERRET_DIST_RELEASE_ENDPOINT`.

The release pipeline now **validates that published assets are anonymously downloadable before a release completes**, so a broken install can no longer ship.

## Install / Upgrade / Uninstall

| Action | Command |
|---|---|
| Install | `npm install -g @indoulia/ferret` |
| Upgrade | `npm update -g @indoulia/ferret` |
| Uninstall | `npm uninstall -g @indoulia/ferret` |

Install locations: Windows `%LOCALAPPDATA%\Programs\Ferret` · macOS `~/Library/Application Support/Ferret` · Linux `~/.local/share/ferret`.

## Assets in this release

- `Ferret-0.16.0-win-x64.zip`, `Ferret-0.16.0-linux-x64.zip`, `Ferret-0.16.0-osx-arm64.zip`, `Ferret-0.16.0-osx-x64.zip` — self-contained, single-file binaries.
- `SHA256SUMS.txt` — checksums for all archives (`sha256sum -c SHA256SUMS.txt`).
- `release-manifest.json` — the machine-readable distribution contract (`schemaVersion: 1`).
- `*.nupkg` — NuGet packages.

## Known limitations

- **macOS binaries are unsigned and unnotarized.** macOS users will see a Gatekeeper prompt; allow the binary in System Settings → Privacy & Security. Signing is deferred to a future milestone.

## Next

The next phase is **dogfooding against real enterprise repositories and documents** — using the parser platform this release delivers to improve search quality, ranking, and overall experience rather than immediately adding more formats.

Reserved for Enterprise Content Pack 2: PowerPoint (`.pptx`), HTML, XML, RTF, YAML/TOML/INI structure-aware parsing. DOCX comments, OCR, and legacy `.doc`/`.xls` remain out of scope.

- 79 parseable text/document extensions
- PDF, Word, and Excel support

- BenchmarkDotNet performance suite
